# 한국어 문장 다듬기

한국어 답변을 내보내기 전에 독자가 앞에서부터 읽으며 뜻을 이해할 수 있도록 다듬는다. 책의 교정 관점과 아래 문장·문단 구성 원칙을 함께 적용한다.

## 문장·문단 구성 원칙

- **문장은 간결하고 명료하게 작성한다.** 핵심 뜻을 직접 전하고 불필요한 수식과 반복을 줄인다. 여러 생각이 얽혀 뜻을 파악하기 어려우면 문장을 나눈다. 필요한 정보와 의미 관계는 유지한다.
- **한 문단에는 하나의 중심 주제를 담는다.** 문단의 핵심을 먼저 밝히고, 뒤따르는 문장은 그 내용을 설명하거나 근거·예시로 뒷받침한다. 주제가 바뀌면 문단을 나눈다.
- **문장은 앞뒤가 자연스럽게 이어지도록 배치한다.** 독자가 이해하는 데 필요한 정보를 먼저 제시하고 설명을 발전시킨다. 문단 안의 각 문장이 중심 주제에 기여하는지 확인한다.

## 적용 방식

- 일반 답변: 요청에 답하는 내용을 먼저 구성하고, 아래 기준으로 문장을 다듬은 결과만 출력한다. 교정했다는 안내나 전후 비교를 매번 덧붙이지 않는다. 한국어 진행 안내에도 같은 기준을 가볍게 적용한다.
- 문장 교정 요청: 사용자가 제공한 글의 뜻과 문체를 살려 교정한다. 사용자가 이유나 비교를 요청하면 바꾼 부분과 이유를 함께 제시한다.
- 원문 그대로 출력하라는 요청, 직접 인용, 코드, 명령, 경로, 식별자, 수식은 보존한다. 주변 설명만 다듬는다. 표·목록·제목을 억지로 완결된 문장으로 바꾸지 않는다.

## 교정 기준

1. **문장 뼈대부터 확인한다.** 누가 무엇을 하거나 어떤 상태인지 주어와 서술어를 맞춘다. 목적어·조사가 서술어와 호응하는지, 나열한 항목들이 같은 서술어에 연결되는지 살핀다. 확인되지 않은 행위자를 만들어 넣지는 않는다.
2. **읽는 순서에 맞춰 펼친다.** 긴 관형절과 명사 나열을 풀고, 꾸미는 말을 꾸밈받는 말 가까이 둔다. 시간 순서·조건·원인과 결과를 읽는 도중 되짚지 않도록 배치한다. 앞 문장과 대화에서 이미 분명한 정보까지 반복할 필요는 없다.
3. **뜻을 더하지 않는 표현만 줄인다.** `-적`, `-의`, `것`, `-들`, `있다`, `-에 대한`, `-에 있어`, `-에 의한`, `-을 하다`, 겹친 피동·사동 등을 살핀다. 삭제 후 뜻·강조·관계가 달라지면 남기거나 문장 전체를 다시 짠다. 단어 목록에 따른 일괄 치환은 하지 않는다.
4. **문장 안에 기준점을 둔다.** `이것`, `그`, `이렇게`가 무엇을 가리키는지, 비율의 기준 집단과 비교 대상이 무엇인지 확인한다. 근거가 있는 내용만 명시한다. 모호한 사용자 원문을 교정할 때는 뜻을 임의로 확정하지 말고 필요한 부분만 짧게 확인한다.
5. **의미 보존을 마지막에 확인한다.** 사실·수치·단위·범위·부정·조건·시제·진행 여부·인과·확신 정도·책임 주체를 원래 내용과 비교한다. 계획을 완료로, 가능성을 사실로, 상관관계를 인과로 바꾸지 않는다. 존댓말과 요청된 분위기를 유지하고 읽기 편해졌으면 멈춘다.

## 자세한 판단이 필요할 때

- 표현별 수정과 유지 조건, 기본 문장 구조, 책의 교정 전후 예시는 [references/patterns.md](references/patterns.md)를 읽는다. 구조 문제가 있으면 ‘문장 뼈대와 순서’, 군더더기가 있으면 ‘표현별 판단’을 중심으로 본다.
- 기술 설명·작업 보고에 적용하거나 과잉 교정이 의심되면 [references/ai-examples.md](references/ai-examples.md)의 적용 예시와 보존 사례를 읽는다.

책의 제안은 문장을 살피는 편집 기준으로 사용한다. 특정 표현의 모든 쓰임을 문법 오류라고 단정하지 않는다. 특히 `할 수 있다`, `것 같다`, 피동형, `-고 있다`, `-었던`, `시작하다`는 가능성·추정·관점·시간을 전달할 수 있으므로 길다는 이유로 없애지 않는다.
